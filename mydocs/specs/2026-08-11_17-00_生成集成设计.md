## 1. Requirements

- **Goal**: 补上 RAG 的 "G"（Generation）--从纯检索器升级为完整检索+生成链路，用户提问后得到带引用回链的 AI 生成答案。
- **In-Scope**:
  1. models 表新建（JSONB parameters + AES-256-GCM 加密）
  2. KB 表新增 embedding_model_id + chat_model_id 必填字段
  3. MVP env var 配置模型，启动时写入 models 表
  4. Agent Pipeline 插件化骨架（EventManager + Plugin + ChatContext）
  5. 5 个 MVP Plugin：SearchPlugin / FilterTopKPlugin / IntoChatMessagePlugin / GeneratePlugin / FormatCitationsPlugin
  6. XML 结构化上下文渲染
  7. 编号引用回链（[N] + SSE done 补发 citations）
  8. 严格模式 system Prompt + 无结果兜底
  9. SSE 流式输出
  10. chat API 端点 `POST /api/v1/kb/{kb_id}/chat`
  11. Key 失效处理
  12. 旧 search API 丢弃，ChunkHit 替换为 RetrievalResult
- **Out-of-Scope**: 多轮对话 / 查询重写 / Rerank / Web 搜索 / BYOK / admin UI 模型管理 / 双层句柄引用

### Acceptance Criteria
1. `POST /api/v1/kb/{kb_id}/chat` 可用，返回 SSE 流
2. SSE 含 token 事件（答案文本）和 done 事件（citations 列表）
3. 答案带 [N] 引用标注，citations 含 id/title/source/chunk_id
4. 检索无结果返回固定话术，不调 LLM
5. chat Key 失效返回 SSE error 事件
6. embedding Key 失效降级 BM25，仍能生成
7. models 表 api_key AES-256-GCM 加密
8. KB 创建必须绑定 embedding_model_id + chat_model_id
9. 5 个 Plugin 各自可独立测试
10. 旧 search API 废弃

## 2. Research Findings

### 事实与约束
1. 本项目后端无 LLM 生成调用（grep 零匹配），检索 API 直接返回 ChunkHit 列表
2. WeKnora 生产实践：插件化 chat_pipeline（10 事件）、XML 上下文、双层句柄引用、SSE 流式、cross-encoder rerank
3. WeKnora models 表：parameters JSONB 承载厂商配置，api_key AES-256-GCM 加密，tenant 级，27 Provider
4. WeKnora KB 绑定：embedding_model_id + summary_model_id（chat）NOT NULL，初始化必填
5. P0 检索地基 spec：vector + bm25(pg_search) + RRF + nearby + 嵌入标题前缀。SEARCH 复用此逻辑
6. 当前 ChunkHit 缺 document_title / source_type / citation_id，需替换为 RetrievalResult

### 4.2 Signatures

```python
class ChatContext:
    query: str; kb_id: int; tenant_id: int; limit: int = 5
    chunks: list[RetrievalResult]; prompt: str; answer: str
    citations: list[Citation]; error: str | None

class Plugin:
    async def on_event(self, event: str, context: ChatContext) -> None: ...

class EventManager:
    PIPELINE = ["SEARCH", "FILTER_TOP_K", "INTO_CHAT_MESSAGE", "GENERATE", "FORMAT_CITATIONS"]

class RetrievalResult:
    chunk_id: int; document_id: int; revision_id: int; score: float
    match_type: str; text: str; chunk_index: int
    context: list[RetrievalResult]; document_title: str
    source_type: str; source_locator: dict; citation_id: int | None

class Citation:
    id: int; title: str; source: str; chunk_id: int
```

### 4.4 System Prompt 草案

```
你是一个知识库问答助手。请严格基于以下检索到的上下文回答用户问题。

规则：
1. 只使用上下文中的信息回答，禁止使用先验知识
2. 每句断言后用 [N] 标注引用来源编号
3. 如果上下文中没有足够信息回答问题，回答："根据知识库中的信息，无法回答该问题。"
4. 不要编造、猜测或推断上下文中不存在的内容
```

### 4.5 SSE 事件格式

```
# 正常流
event: token
data: {"text": "该产品型号为 X-100 [1]"}

event: done
data: {"citations": [{"id": 1, "title": "产品规格书", "source": "manual", "chunk_id": 123}]}

# 无结果
event: done
data: {"answer": "根据知识库中的信息，无法回答该问题。", "citations": []}

# Key 失效
event: error
data: {"code": "MODEL_KEY_INVALID", "message": "对话模型 Key 失效，请检查系统配置"}
```

