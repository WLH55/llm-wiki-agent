# RAG / Wiki 数据库表逐表审批记录

> 状态：进行中<br>
> 最后更新：2026-07-27<br>
> 规则：逐表说明用途、字段和生命周期；用户批准前不创建表、不修改 migration。

## 已确认的全局决策

1. Wiki 与 RAG 在 MVP 中独立运行：Wiki 页面不切块、不 embedding、不写入 RAG 召回池。
2. 数据库不建立显式外键约束。表之间保留逻辑引用字段和查询索引；应用服务负责关联校验、删除顺序与孤儿数据巡检。
3. `knowledge_bases` 是轻量共享根，不保存 RAG/Wiki 类型、嵌入模型或能力开关。
4. RAG 与 Wiki 分别使用独立配置表。
5. 同一来源文档的后续上传或同步形成新的不可变 `document_revisions`；只有处理成功的版本才切换为 `documents.active_revision_id`，失败版本不影响旧版本检索。
6. `content_chunks` 只保留当前生效 Revision 的派生分块；历史 Revision 保留原文件但不保留 chunks，新版本成功切换后物理删除旧 chunks。
7. 关键词召回使用 PostgreSQL `pg_search` 扩展在 `content_chunks.text` 上建立真正 BM25 索引；现有 `TSVECTOR + ts_rank_cd` 只是 PostgreSQL 全文排序，不得继续命名为 BM25，最终表不保留 `search_vector`。
8. PostgreSQL 向量检索使用 pgvector HNSW，不使用 IVFFlat；每个支持的 embedding 维度建立独立 partial HNSW。固定 `m=16`、`ef_construction=64`；查询使用 pgvector `>=0.8`，动态设置 `ef_search=clamp(top_k*2,100,200)` 与 `iterative_scan=strict_order`。这些参数均不向 KB 用户开放。
9. 旧代码、旧 migration 与开发数据库数据不要求兼容；所有候选表完成审批后按最终设计重建 schema，当前不修改 migration。
10. `wiki_pages.folder_id` 是页面目录归属的唯一事实来源；页面表不缓存 `category_path`、`depth`、`wiki_path`。页面列表通过普通 JOIN 读取目录信息，Markdown 导出路径在运行时由目录路径与页面 `slug` 组合得到。
11. `wiki_pages.aliases` 使用 `TEXT[] NOT NULL DEFAULT '{}'`，只保存页面标题的其他叫法并辅助搜索；它不决定页面身份、不参与 wikilink 解析，也不要求跨页面唯一。应用层负责去除空白、空字符串和单页内重复值。
12. `wiki_pages` 不保留 `parent_slug`。页面目录层级由 `folder_id` 表达，页面之间的语义关系统一由 `wiki_page_links` 表达，避免两套关系重叠以及 slug 改名、单父级和循环引用问题。
13. `wiki_pages` 将通用页面预览字段命名为 `excerpt TEXT NULL`，不使用容易与 `page_type='summary'` 混淆的 `summary` 字段。`excerpt` 用于目录列表、搜索结果和 Agent 选页；`content` 保存完整 Markdown 正文。

## 已批准表摘要

### `knowledge_bases`

保留内部 BIGINT ID 与对外 UUID；保存归属、名称、描述和软删除时间。不保存 `type`、embedding 字段或 `*_enabled` 开关。

### `kb_rag_configs`

保存 `enabled`、`vector_enabled`、`keyword_enabled`、`embedding_model_key`、`embedding_dim`、`chunking_strategy`、`chunk_size_tokens`、`chunk_overlap_tokens`、`chunking_options` 和 `config_version`。不保存 Wiki 配置、top-k、RRF 参数或 boost。

### `kb_wiki_configs`

保存 `enabled`、`generation_mode`、`generation_model_key`、`generation_options` 和 `config_version`。MVP 的生成模式为 `manual` 或 `on_ingest`；不包含 embedding 或 Wiki chunk boost。

### `sources`

保存来源身份、`source_type`、显示名称、启停状态、适配器配置、增量同步游标、配置版本和最近成功同步时间。敏感凭据只保存引用，不写入 `config` 明文。

### `documents`

`documents` 表示来源文档在 KB 中的稳定身份，同一来源文档更新时不删除重建。批准字段如下：

| 字段 | 类型 | 可空/默认值 | 说明 |
|---|---|---|---|
| `id` | `BIGINT` | PK，identity | 内部关联 ID |
| `public_id` | `UUID` | NOT NULL，自动生成 | API 对外文档 ID，全局唯一 |
| `tenant_id` | `BIGINT` | NOT NULL | 租户逻辑引用 |
| `kb_id` | `BIGINT` | NOT NULL | KB 逻辑引用 |
| `source_id` | `BIGINT` | NOT NULL | Source 逻辑引用 |
| `source_document_key` | `VARCHAR(512)` | NOT NULL | 来源系统中的稳定文档标识；手动上传时生成，不使用文件名充当身份 |
| `title` | `VARCHAR(500)` | NOT NULL | 当前展示标题 |
| `active_revision_id` | `BIGINT` | NULL | 当前正式用于检索的成功版本；首次处理成功前为空 |
| `version` | `INTEGER` | NOT NULL，默认 `1` | 修改文档元数据时的乐观锁 |
| `created_at` | `TIMESTAMPTZ` | NOT NULL，默认 `now()` | 创建时间 |
| `updated_at` | `TIMESTAMPTZ` | NOT NULL，默认 `now()` | 更新时间 |
| `deleted_at` | `TIMESTAMPTZ` | NULL | 软删除时间 |

约束与索引：`public_id` 全局唯一；`(source_id, source_document_key)` 在未删除记录中唯一；分别为 `tenant_id`、`kb_id`、`source_id`、`active_revision_id` 建查询索引。不保存文档级 `status` 或无明确契约的 `attributes JSONB`；文件和处理信息归属具体 Revision。

### `document_revisions`

`document_revisions` 表示一次上传或同步取得的内容快照。原文件事实不可修改，处理状态与诊断字段可随流水线更新。批准字段如下：

| 字段 | 类型 | 可空/默认值 | 说明 |
|---|---|---|---|
| `id` | `BIGINT` | PK，identity | 内部版本 ID |
| `document_id` | `BIGINT` | NOT NULL | Document 逻辑引用 |
| `revision_no` | `INTEGER` | NOT NULL，且 `>= 1` | 文档内单调递增版本号 |
| `source_version` | `VARCHAR(255)` | NULL | 来源系统提供的 revision ID、ETag 等幂等标识 |
| `source_updated_at` | `TIMESTAMPTZ` | NULL | 来源系统声明的修改时间 |
| `original_filename` | `VARCHAR(500)` | NOT NULL | 本版本收到的原始文件名 |
| `media_type` | `VARCHAR(255)` | NOT NULL | MIME 类型 |
| `size_bytes` | `BIGINT` | NOT NULL，且 `>= 0` | 原文件字节数 |
| `content_sha256` | `CHAR(64)` | NOT NULL | 原文件内容指纹 |
| `storage_key` | `VARCHAR(1000)` | NOT NULL | 对象存储中的不可变 key |
| `parser_engine` | `VARCHAR(50)` | NOT NULL，默认 `builtin` | 本版本选择的解析引擎 |
| `status` | `VARCHAR(20)` | NOT NULL，默认 `pending` | `pending` / `processing` / `ready` / `failed` |
| `error_code` | `VARCHAR(50)` | NULL | 稳定机器错误码 |
| `error_message` | `VARCHAR(1000)` | NULL | 诊断文本 |
| `parse_metadata` | `JSONB` | NOT NULL，默认 `{}` | parser metadata、warnings 与持久化图片清单，禁止 base64 |
| `processing_started_at` | `TIMESTAMPTZ` | NULL | 开始处理时间 |
| `processed_at` | `TIMESTAMPTZ` | NULL | 成功或失败的结束时间 |
| `created_by_user_id` | `BIGINT` | NULL | 手动上传者；自动同步时为空 |
| `created_at` | `TIMESTAMPTZ` | NOT NULL，默认 `now()` | 版本创建时间 |
| `updated_at` | `TIMESTAMPTZ` | NOT NULL，默认 `now()` | 状态或诊断更新时间 |
| `deleted_at` | `TIMESTAMPTZ` | NULL | 软删除时间 |

约束与索引：`UNIQUE(document_id, revision_no)`；有 `source_version` 时，未删除记录中 `UNIQUE(document_id, source_version)`；`storage_key` 全局唯一；分别为 `document_id`、`content_sha256` 建索引。内容哈希不设唯一约束，由应用层将相同内容视为幂等同步，同时允许失败任务合法重试。

生命周期：创建 Revision 后依次进入 `pending -> processing -> ready|failed`。只有 `ready` 才能在同一事务中写入 `documents.active_revision_id`；新版本失败时继续使用旧生效版本。解析重试不创建新 Revision，后续 `processing_runs` 负责记录每次处理尝试。

### `content_chunks`

只保存当前生效 Document Revision 的可重建检索分块；chunk 创建后不可原地修改，新版本切换时物理删除旧 chunks。批准字段如下：

| 字段 | 类型 | 可空/默认值 | 说明 |
|---|---|---|---|
| `id` | `BIGINT` | PK，identity | 内部 ID，也是 pg_search BM25 `key_field` |
| `public_id` | `UUID` | NOT NULL，自动生成 | API 对外 chunk ID，全局唯一 |
| `tenant_id` | `BIGINT` | NOT NULL | 租户过滤 |
| `kb_id` | `BIGINT` | NOT NULL | KB 过滤 |
| `source_id` | `BIGINT` | NOT NULL | 来源过滤 |
| `document_id` | `BIGINT` | NOT NULL | 逻辑文档引用 |
| `revision_id` | `BIGINT` | NOT NULL | 生效文档版本引用 |
| `processing_run_id` | `BIGINT` | NOT NULL | 生成本 chunk 的处理运行 |
| `chunk_index` | `INTEGER` | NOT NULL，且 `>= 0` | 文档内从 0 开始的顺序 |
| `text` | `TEXT` | NOT NULL，非空 | BM25 原文、embedding 输入和返回给 LLM 的正文 |
| `token_count` | `INTEGER` | NOT NULL，且 `>= 0` | 上下文 token 预算 |
| `text_sha256` | `CHAR(64)` | NOT NULL | 文本指纹，用于 embedding 缓存与重复检测 |
| `source_locator` | `JSONB` | NOT NULL，默认 `{}` | PDF 页码、Excel sheet/行号、Markdown 标题路径等原文位置 |
| `embedding` | `HALFVEC` | NULL | 语义向量；仅关键词检索时为空 |
| `embedding_dim` | `INTEGER` | NULL，存在时 `> 0` | 与 embedding 同时为空或同时存在 |
| `created_at` | `TIMESTAMPTZ` | NOT NULL，默认 `now()` | 生成时间 |

约束：`UNIQUE(public_id)`、`UNIQUE(revision_id, chunk_index)`；正文去除空白后不能为空；`embedding` 与 `embedding_dim` 必须同时为空或同时有效。不建立外键，不保留 `chunk_type`、`wiki_page_id`、`is_active`、`updated_at`、`deleted_at` 或 `search_vector`。

普通索引：`(tenant_id, kb_id)`、`source_id`、`(document_id, chunk_index)`、`(revision_id, chunk_index)`、`processing_run_id`。

关键词索引：PostgreSQL `pg_search` 对 `id`、过滤字段和 `text` 建立真正 BM25 索引，使用固定版本的中文 tokenizer；不使用 `TSVECTOR + GIN`。

向量索引：pgvector `>=0.8`，每个受支持维度建立 partial HNSW cosine 索引；固定 `m=16`、`ef_construction=64`，查询动态设置 `ef_search=clamp(top_k*2,100,200)` 与 `iterative_scan=strict_order`。不使用 IVFFlat，不向 KB 用户开放物理索引参数。

### `wiki_pages`

保存 Wiki 页面的稳定身份、类型、展示内容、目录归属和编辑并发状态。批准字段如下：

| 字段 | 类型 | 可空/默认值 | 说明 |
|---|---|---|---|
| `id` | `BIGINT` | PK，identity | 内部关联 ID |
| `public_id` | `UUID` | NOT NULL，自动生成 | API 对外稳定页面 ID；修改 slug 后保持不变 |
| `tenant_id` | `BIGINT` | NOT NULL | 租户逻辑引用与隔离过滤 |
| `kb_id` | `BIGINT` | NOT NULL | KB 逻辑引用 |
| `page_type` | `VARCHAR(20)` | NOT NULL | `summary` / `entity` / `concept` / `index` / `log` / `synthesis` / `comparison` |
| `slug` | `VARCHAR(255)` | NOT NULL，非空 | KB 内稳定页面标识，用于 URL 与 wikilink |
| `title` | `VARCHAR(500)` | NOT NULL，非空 | 用户看到的页面标题 |
| `aliases` | `TEXT[]` | NOT NULL，默认 `{}` | 简称、旧称和中英文名称，只辅助搜索 |
| `excerpt` | `TEXT` | NULL | 页面简短预览，用于目录列表、搜索结果和 Agent 选页 |
| `content` | `TEXT` | NOT NULL，默认 `''` | 完整 Markdown 正文 |
| `folder_id` | `BIGINT` | NULL | 页面真实目录归属；NULL 表示 Wiki 根目录或无普通目录的系统页 |
| `sort_order` | `INTEGER` | NOT NULL，默认 `0` | 同一目录内的人工排序权重 |
| `version` | `INTEGER` | NOT NULL，默认 `1`，且 `>= 1` | 编辑乐观锁；成功修改后递增 |
| `created_by_user_id` | `BIGINT` | NULL | 创建者；系统或 Agent 创建时为空 |
| `updated_by_user_id` | `BIGINT` | NULL | 最近一次人工修改者；系统更新时为空 |
| `generation_run_id` | `BIGINT` | NULL | 最近一次写入该页面的 Wiki 生成运行 |
| `created_at` | `TIMESTAMPTZ` | NOT NULL，默认 `now()` | 首次创建时间 |
| `updated_at` | `TIMESTAMPTZ` | NOT NULL，默认 `now()` | 最近更新时间 |
| `deleted_at` | `TIMESTAMPTZ` | NULL | 软删除时间 |

约束：`public_id` 全局唯一；未删除页面中 `UNIQUE(kb_id, slug)`；`page_type` 只能取已批准的 7 个值；`slug` 与 `title` 去除首尾空白后不能为空；单页 `aliases` 由应用层去除空白、空字符串和重复值。`index`、`log` 是系统保留 slug，普通用户不能占用。按全局规则，逻辑引用不建立数据库外键。

索引：`(tenant_id, kb_id)`、`(kb_id, page_type)`、`(kb_id, folder_id, sort_order, id)`、`generation_run_id`；唯一索引按上述约束建立。

字段边界：`page_type='summary'` 表示整张页面是文档摘要页，`excerpt` 是任何页面都可具有的简短预览，`content` 是完整正文。页面不保留 `status`、`parent_slug`、`category_path`、`depth`、`wiki_path`、`in_links`、`out_links`、`source_refs`、`chunk_refs`、`page_metadata` 或 `embedding`。页面链接和文档/chunk 溯源由后续独立表保存。
