## 已确认的全局决策

1. Wiki 与 RAG 在 MVP 中保持独立的下游执行和检索路径，但共享 Active Revision 的 `content_chunks` 摄取底座。Wiki 页面本身不切块、不 embedding、不写回 `content_chunks`，也不进入 RAG 召回池。
2. 全库不建立显式外键约束（含基础设施/预留表）。表之间保留逻辑引用字段和查询索引；应用服务负责关联校验、删除顺序与孤儿数据巡检，不得依赖数据库级联删除或外键报错保证一致性（ADR-0011，2026-08-02 扩展为全库范围）。
3. `knowledge_bases` 是 RAG/Wiki 共享根，保存通用身份与唯一的共享分块策略；不保存 RAG/Wiki 类型、embedding 模型或能力开关。
4. RAG 与 Wiki 分别使用独立配置表；共享分块策略不属于任一下游路径，由 `knowledge_bases` 统一定义。
5. 同一来源文档的后续上传或同步形成新的不可变 `document_revisions`。完成原文解析与共享分块后 Revision 进入 `ready` 并成为候选版本；未启用向量检索时立即激活，启用向量检索时必须先完成候选 chunks 的 `rag_index`，再原子切换 `documents.active_revision_id`。Wiki 生成不是激活门槛，并在激活后独立运行。
6. `content_chunks` 只保留当前 Active Revision 的可重建共享内容块，同时作为 RAG 召回单元与 Wiki Map 输入。历史 Revision 保留原文件但不长期保留 chunks，新版本成功切换后物理删除旧 chunks。
7. 关键词召回使用 PostgreSQL `pg_search` 扩展在 `content_chunks.text` 上建立真正 BM25 索引；现有 `TSVECTOR + ts_rank_cd` 只是 PostgreSQL 全文排序，不得继续命名为 BM25，最终表不保留 `search_vector`。
8. PostgreSQL 向量检索使用 pgvector HNSW，不使用 IVFFlat；每个支持的 embedding 维度建立独立 partial HNSW。固定 `m=16`、`ef_construction=64`；查询使用 pgvector `>=0.8`，动态设置 `ef_search=clamp(top_k*2,100,200)` 与 `iterative_scan=strict_order`。这些参数均不向 KB 用户开放。
9. 旧代码、旧 migration 与开发数据库数据不要求兼容；所有候选表完成审批后按最终设计重建 schema，当前不修改 migration。
10. `wiki_pages.folder_id` 是页面目录归属的唯一事实来源；页面表不缓存 `category_path`、`depth`、`wiki_path`。页面列表通过普通 JOIN 读取目录信息，Markdown 导出路径在运行时由目录路径与页面 `slug` 组合得到。
11. `wiki_pages.aliases` 使用 `TEXT[] NOT NULL DEFAULT '{}'`，只保存页面标题的其他叫法并辅助搜索；它不决定页面身份、不参与 wikilink 解析，也不要求跨页面唯一。应用层负责去除空白、空字符串和单页内重复值。
12. `wiki_pages` 不保留 `parent_slug`。页面目录层级由 `folder_id` 表达，页面之间的语义关系统一由 `wiki_page_links` 表达，避免两套关系重叠以及 slug 改名、单父级和循环引用问题。
13. `wiki_pages` 将通用页面预览字段命名为 `excerpt TEXT NULL`，不使用容易与 `page_type='summary'` 混淆的 `summary` 字段。`excerpt` 用于目录列表、搜索结果和 Agent 选页；`content` 保存完整 Markdown 正文。
14. 所有对外稳定 UUID 字段统一命名为 `public_id`；`knowledge_bases`、`sources`、`documents`、`content_chunks`、`wiki_pages` 不再混用 `uid`。
15. MVP 中 `wiki_pages.slug` 创建后不可修改；页面改名只修改 `title` 和 `aliases`。wikilink 始终使用不可变 slug，避免批量重写其他页面正文、导出链接失效和 slug 重用歧义。
16. wikilink 在保存 `wiki_pages.content` 的同一事务中同步解析并刷新关系，不使用异步链接解析任务，因此 `wiki_page_links` 不保存 `source_page_version`。
17. `wiki_page_links` 是从页面正文同步派生的独立有向边表，支持 `to_page_id IS NULL` 的悬空链接；同一来源页面到同一 `target_slug` 只保存一条边，不保存类型、权重或页面内链接数组。
18. Wiki 生成逻辑上覆盖完整 Active Revision：按 `content_chunks.chunk_index` 顺序遍历所有块，按 Wiki token 预算将相邻 chunks 组合为 Map 批次，执行“批次级 Map -> 文档级 Reduce -> 跨文档按 slug Reduce”，禁止重建整文后直接截断。MVP 不保存跨运行 checkpoint；Map 中间结果只存在于当前 Worker 内存，失败或进程退出后从同一 Active Chunk Set 完整重做。Redis 只承担 RQ 队列、同 KB Wiki 租约锁和删除墓碑，不保存业务进度、Map 结果或其他唯一业务副本。
19. `wiki_page_evidence_refs` 长期证据以具体 `revision_id`、从共享 chunk 核验复制的 `evidence_quote` 和 `source_locator` 为基础。`content_chunk_id BIGINT NULL` 记录生成当时的共享 chunk 快捷逻辑关联，MVP 生成证据时填充；chunk 被物理删除时清空该字段，Revision、准确引文和位置继续使证据有效。
20. `wiki_page_evidence_refs` 不保存 `citation_no`。MVP 尚未批准在 `wiki_pages.content` 中使用数字引用标记；来源列表如需 `[1]`、`[2]` 等展示编号，由查询或渲染层按确定性顺序动态生成，避免增删证据时同步重写正文和持久化编号。
21. `wiki_folders` 保留不可变 `slug` 作为稳定、文件系统安全的导出路径段；展示改名只修改 `name`，目录移动只修改 `parent_id` 并由应用阻止循环。
22. `processing_runs` 使用 `run_type` 表达处理流程，并使用通用 `scope_type + scope_id` 表达处理目标。`document_process` 负责生成 `ready` 候选 Revision 和共享 chunks；启用向量检索时，`rag_index` 成功触发原子激活，未启用时由 `document_process` 直接激活；`wiki_generate` 在激活后独立运行。
23. `processing_spans` 只保存阶段树、状态、时间、模型 token 和结构化数值指标；原文、Prompt、完整模型响应、堆栈与完整日志进入各自内容存储或外部日志系统。
24. `search_logs` 不保存未经处理的原始查询和完整命中正文；保存可空脱敏查询、租户密钥 HMAC 指纹及只含公开 ID、排名、分数和召回通道的命中快照，并通过 `expires_at` 物理清理。
25. `document_revisions` 不重复保存运行级错误和起止时间，删除 `error_code`、`error_message`、`processing_started_at`、`processed_at`；`processing_runs` 不保存含义不稳定的主要模型，删除 `model_key`。
26. RQ 自动重试属于同一 `processing_run` 的再次执行，不创建新 Run、不递增 `attempt_no`；等待自动重试时 Run 回到 `pending`，Worker 重新取得任务后回到 `running`。只有终态 Run 之后由用户或系统发起的业务重跑才创建新 Run，并填写 `retry_of_run_id`、递增 `attempt_no`。
27. `processing_spans.status` 使用 `pending` / `running` / `succeeded` / `failed` / `skipped` / `cancelled`。`skipped` 只表示配置或输入决定的主动跳过；`cancelled` 表示用户取消、Run 取消或上游失败造成的中止。未开始便结束的 Span 没有真实开始时间，因此 `started_at` 允许为空。
28. `processing_spans` 删除 `sequence_no` 及 `UNIQUE(run_id, sequence_no)`。固定业务阶段的展示顺序来自应用阶段注册表，依赖来自编排代码，父子关系来自 `parent_span_id`；同级记录按 `created_at, id` 稳定排序。
29. Active Revision 使用两阶段激活：候选 Revision 完成共享解析和分块后进入 `ready`；启用向量检索时必须先成功写入完整 embedding，再在一个事务中切换 `active_revision_id`、清理旧 chunks。embedding 失败时保留旧 Active Revision 及其向量，候选 chunks 留待重试或后续清理；Wiki 失败不影响已完成的激活。
30. 同一 KB 的 Wiki 生成使用 Redis 租约锁串行化。锁值包含 Run 身份和随机 execution token，带 TTL；续租和释放必须原子校验 token，失锁 Worker 禁止提交。文档删除墓碑只用于让排队中或执行中的 Worker 快速中止。最终 Wiki 事务仍须校验 KB、Document、Revision、Active Revision 和 Run 状态，并使用页面 `version` 乐观锁；不新增表字段或 `processing_runs` 运行中唯一索引。

## 已批准表摘要

### `knowledge_bases`

`knowledge_bases` 是 RAG 与 Wiki 共享的聚合根，保存身份、归属、通用描述和唯一的共享分块策略。分块属于文档摄取，不属于 RAG 或 Wiki 任一下游能力。批准字段如下：

| 字段 | 类型 | 可空/默认值 | 说明 |
|---|---|---|---|
| `id` | `BIGINT` | PK，identity | 内部关联 ID |
| `public_id` | `UUID` | NOT NULL，自动生成 | API、日志和导出使用的稳定公开 ID，全局唯一 |
| `tenant_id` | `BIGINT` | NOT NULL | 租户逻辑引用 |
| `name` | `VARCHAR(200)` | NOT NULL | 用户可见的 KB 名称 |
| `description` | `TEXT` | NOT NULL，默认 `''` | KB 通用说明（使用 TEXT，不限长度） |
| `chunking_strategy` | `VARCHAR(50)` | NOT NULL | 共享分块算法标识，例如 `recursive_tokens` / `markdown_heading` / `fixed_tokens` / `parent_child` |
| `chunk_size_tokens` | `INTEGER` | NOT NULL | 单个共享 chunk 的目标 token 上限 |
| `chunk_overlap_tokens` | `INTEGER` | NOT NULL | 相邻共享 chunk 重复保留的 token 数 |
| `chunking_options` | `JSONB` | NOT NULL，默认 `{}` | 当前分块策略的专属扩展参数，按策略 JSON Schema 校验 |
| `chunking_config_version` | `INTEGER` | NOT NULL，默认 `1` | 共享分块配置修订号，用于并发更新与重建追踪 |
| `created_at` | `TIMESTAMPTZ` | NOT NULL，默认 `now()` | 创建时间 |
| `updated_at` | `TIMESTAMPTZ` | NOT NULL，默认 `now()` | 更新时间 |
| `deleted_at` | `TIMESTAMPTZ` | NULL | 软删除时间 |

约束与索引：`public_id` 全局唯一；`chunk_size_tokens > 0`，`0 <= chunk_overlap_tokens < chunk_size_tokens`，`chunking_config_version >= 1`；为 `tenant_id` 和未删除 KB 查询建立索引。分块策略必须在应用注册表中，选项按对应 JSON Schema 校验。按全局规则，逻辑引用不建立数据库外键。

生命周期：修改共享分块策略时递增 `chunking_config_version`，并通过新 `document_process` Run 为各 Active Revision 重建 chunk set。旧分块在新分块完整写入并切换后物理删除；RAG/Wiki 下游任务不能各自覆盖分块策略。

字段边界：不保存 `type`、embedding 模型、embedding 维度或 `vector_enabled` / `keyword_enabled` / `wiki_enabled` / `graph_enabled`。RAG 与 Wiki 能力分别由独立配置表表达。

### `kb_rag_configs`

`kb_rag_configs` 保存只属于 RAG 路径的启停、embedding 和召回配置。共享分块策略已移至 `knowledge_bases`，本表不得定义另一套分块规则。批准字段如下：

| 字段 | 类型 | 可空/默认值 | 说明 |

| `keyword_enabled` | `BOOLEAN` | NOT NULL，默认 `true` | 是否建立关键词索引并启用 BM25 召回 |
| `embedding_model_key` | `VARCHAR(200)` | NULL | embedding adapter 使用的稳定模型标识 |
| `embedding_dim` | `INTEGER` | NULL | 模型输出维度；由模型注册信息写入，不由用户手填 |

字段边界：不保存 Wiki 配置、分块策略、top-k、RRF 参数、物理 HNSW 参数或 boost factor。

### `kb_wiki_configs`

| 字段 | 类型 | 可空/默认值 | 说明 |

| `generation_mode` | `VARCHAR(20)` | NOT NULL，默认 `manual` | `manual` 或 `on_ingest` |
| `generation_model_key` | `VARCHAR(200)` | NULL | 自动生成 Wiki 页面使用的 LLM；NULL 表示使用系统默认模型 |
| `generation_options` | `JSONB` | NOT NULL，默认 `{}` | 自动生成页面类型、输出语言和 prompt profile 等策略参数 |
| `config_version` | `INTEGER` | NOT NULL，默认 `1` | Wiki 配置修订号 |
| `created_at` | `TIMESTAMPTZ` | NOT NULL，默认 `now()` | 创建时间 |

业务校验：`generation_mode` 只能是 `manual` 或 `on_ingest`；自动生成任务必须解析出可用的具体模型，并在处理运行中记录实际模型与配置版本。逻辑引用不建立数据库外键。

字段边界：不保存 embedding 配置、RAG 召回开关、Wiki chunk boost、图谱抽取配置或每 KB 搜索权重。

| `kb_id` | `BIGINT` | NOT NULL | KB 逻辑引用 |
| `source_id` | `BIGINT` | NOT NULL | Source 逻辑引用 |
| `source_document_key` | `VARCHAR(512)` | NOT NULL | 来源系统中的稳定文档标识；手动上传时生成，不使用文件名充当身份 |
| `title` | `VARCHAR(500)` | NOT NULL | 当前展示标题 |
| `active_revision_id` | `BIGINT` | NULL | 当前已通过激活门槛、正式供 RAG/Wiki 使用的版本；首次激活成功前为空 |
| `version` | `INTEGER` | NOT NULL，默认 `1` | 修改文档元数据时的乐观锁 |
| `created_at` | `TIMESTAMPTZ` | NOT NULL，默认 `now()` | 创建时间 |

约束与索引：`public_id` 全局唯一；`(source_id, source_document_key)` 在未删除记录中唯一；分别为 `tenant_id`、`kb_id`、`source_id`、`active_revision_id` 建查询索引。不保存文档级 `status` 或无明确契约的 `attributes JSONB`；文件和处理信息归属具体 Revision。

### `document_revisions`

`document_revisions` 表示一次上传或同步取得的内容快照。原文件事实不可修改，`status` 只表达该快照能否成为生效版本；每次处理尝试的错误和执行时间归 `processing_runs`。批准字段如下：

| 字段 | 类型 | 可空/默认值 | 说明 |
|---|---|---|---|
| `id` | `BIGINT` | PK，identity | 内部版本 ID |
| `document_id` | `BIGINT` | NOT NULL | Document 逻辑引用 |
| `revision_no` | `INTEGER` | NOT NULL，且 `>= 1` | 文档内单调递增版本号 |
| `source_version` | `VARCHAR(255)` | NULL | 来源系统提供的 revision ID、ETag 等幂等标识 |
| `source_updated_at` | `TIMESTAMPTZ` | NULL | 来源系统声明的修改时间 |
| `original_filename` | `VARCHAR(500)` | NOT NULL | 本版本收到的原始文件名 |
| `media_type` | `VARCHAR(255)` | NOT NULL | MIME 类型 |
| `size_bytes` | `BIGINT` | NOT NULL，且 `>= 0` | 原文件字节数 |
| `content_sha256` | `CHAR(64)` | NOT NULL | 原文件内容指纹 |
| `storage_key` | `VARCHAR(1000)` | NOT NULL | 对象存储中的不可变 key |
| `parser_engine` | `VARCHAR(50)` | NOT NULL，默认 `builtin` | 本版本选择的解析引擎 |
| `status` | `VARCHAR(20)` | NOT NULL，默认 `pending` | `pending` / `processing` / `ready` / `failed` |
| `parse_metadata` | `JSONB` | NOT NULL，默认 `{}` | parser metadata、warnings 与持久化图片清单，禁止 base64 |
| `created_by_user_id` | `BIGINT` | NULL | 手动上传者；自动同步时为空 |
| `created_at` | `TIMESTAMPTZ` | NOT NULL，默认 `now()` | 版本创建时间 |
| `updated_at` | `TIMESTAMPTZ` | NOT NULL，默认 `now()` | 状态或解析元数据更新时间 |
| `deleted_at` | `TIMESTAMPTZ` | NULL | 软删除时间 |

约束与索引：`UNIQUE(document_id, revision_no)`；有 `source_version` 时，未删除记录中 `UNIQUE(document_id, source_version)`；`storage_key` 全局唯一；分别为 `document_id`、`content_sha256` 建索引。内容哈希不设唯一约束，由应用层将相同内容视为幂等同步，同时允许失败任务合法重试。

生命周期：创建 Revision 后依次进入 `pending -> processing -> ready|failed`。`ready` 表示原文解析和共享 chunk set 已完整写入，可以作为候选版本，但不等于已经 Active。未启用向量检索时，`ready` 后立即激活；启用向量检索时，候选 chunks 的 `rag_index` 成功后才激活。RAG/Wiki 下游 Run 不改写 Revision 的 `ready`。共享解析、分块或激活前 embedding 失败时继续使用旧 Active Revision。解析重试不创建新 Revision，`processing_runs` 记录每次尝试及其错误和起止时间。

### `content_chunks`

保存 Document Revision 的可重建共享内容块：RAG 将其作为 BM25/embedding 召回单元，Wiki 将其作为完整遍历文档的 Map 输入。长期保留 Active Revision 的 chunk set；两阶段激活期间还允许一套 `ready` 候选 chunks 与旧 Active chunks 共存。所有在线 RAG/Wiki 读取必须通过 `documents.active_revision_id = content_chunks.revision_id` 过滤，候选 chunks 只供激活前索引任务使用。批准字段如下：

| 字段 | 类型 | 可空/默认值 | 说明 |
|---|---|---|---|
| `id` | `BIGINT` | PK，identity | 内部 ID，也是 pg_search BM25 `key_field` |
| `public_id` | `UUID` | NOT NULL，自动生成 | API 对外 chunk ID，全局唯一 |
| `tenant_id` | `BIGINT` | NOT NULL | 租户过滤 |
| `kb_id` | `BIGINT` | NOT NULL | KB 过滤 |
| `source_id` | `BIGINT` | NOT NULL | 来源过滤 |
| `document_id` | `BIGINT` | NOT NULL | 逻辑文档引用 |
| `revision_id` | `BIGINT` | NOT NULL | 生效文档版本引用 |
| `processing_run_id` | `BIGINT` | NOT NULL | 解析并生成本共享 chunk 的 `document_process` Run |
| `embedding_run_id` | `BIGINT` | NULL | 最近一次写入当前 embedding 的 `rag_index` Run；未向量化时为空 |
| `chunk_index` | `INTEGER` | NOT NULL，且 `>= 0` | 文档内从 0 开始的顺序 |
| `text` | `TEXT` | NOT NULL，非空 | 共享原文块；同时作为 BM25 原文、embedding 输入和 Wiki Map 输入 |
| `token_count` | `INTEGER` | NOT NULL，且 `>= 0` | 上下文 token 预算 |
| `text_sha256` | `CHAR(64)` | NOT NULL | 文本指纹，用于 embedding 缓存与重复检测 |
| `source_locator` | `JSONB` | NOT NULL，默认 `{}` | PDF 页码、Excel sheet/行号、Markdown 标题路径等原文位置 |
| `embedding` | `HALFVEC` | NULL | RAG 语义向量；Wiki-only、仅关键词或尚未完成向量化时为空 |
| `embedding_dim` | `INTEGER` | NULL，存在时 `> 0` | 与 embedding 同时为空或同时存在 |
| `created_at` | `TIMESTAMPTZ` | NOT NULL，默认 `now()` | 生成时间 |
| `updated_at` | `TIMESTAMPTZ` | NOT NULL，默认 `now()` | embedding 写入或重建的最近更新时间 |

约束：`UNIQUE(public_id)`、`UNIQUE(revision_id, chunk_index)`；正文去除空白后不能为空；`embedding`、`embedding_dim` 与 `embedding_run_id` 必须三者同时为空或同时有效。不建立外键，不保留 `chunk_type`、`wiki_page_id`、`is_active`、`deleted_at` 或 `search_vector`。

普通索引：`(tenant_id, kb_id)`、`source_id`、`(document_id, chunk_index)`、`(revision_id, chunk_index)`、`processing_run_id`、`embedding_run_id IS NOT NULL` 的 partial index。

关键词索引：PostgreSQL `pg_search` 对 `id`、过滤字段和 `text` 建立真正 BM25 索引，使用固定版本的中文 tokenizer；不使用 `TSVECTOR + GIN`。Wiki-only chunks 也会进入物理 BM25 索引，但当 `kb_rag_configs` 不存在或未启用时，应用不得暴露 `knowledge_search`。这是不新增分块表所接受的存储代价。

向量索引：pgvector `>=0.8`，每个受支持维度建立 partial HNSW cosine 索引；固定 `m=16`、`ef_construction=64`，查询动态设置 `ef_search=clamp(top_k*2,100,200)` 与 `iterative_scan=strict_order`。不使用 IVFFlat，不向 KB 用户开放物理索引参数。共享 chunk 先以空 embedding 写入，`rag_index` 子 Run 只允许修改 `embedding`、`embedding_dim`、`embedding_run_id` 和 `updated_at`。启用向量检索时，候选 Revision 的全部 chunks 必须具有同一成功 `rag_index` Run 写入的有效向量后才能激活；在线向量召回仍只读取 Active Revision。

生命周期：共享解析阶段以稳定 `chunk_index`、准确 `source_locator` 和空 embedding 写入新 Revision 的完整候选 chunk set。写入失败时删除本次候选 chunks，不切换 Active Revision；写入成功后将 Revision 标记为 `ready`。未启用向量检索时立即执行激活事务；启用向量检索时先由 `rag_index` 为整套候选 chunks 写入向量，成功后再执行激活事务。激活事务依次清空旧 chunks 的证据快捷关联、切换 `documents.active_revision_id` 并物理删除旧 chunk set。embedding 失败时旧 Active chunks 与旧向量继续服务，候选 chunks 保留供业务重跑；同一 Document 出现更新候选或被删除时，应用清理不再可能激活的候选 chunks。`wiki_generate` 只消费激活后的 Chunk Set，其失败不回滚激活。

| 字段 | 类型 | 可空/默认值 | 说明 |

### `wiki_page_links`

保存从 `wiki_pages.content` 中的 `[[slug|显示文字]]` 同步解析出的页面间有向关系。页面正文是事实来源，本表是可重建查询索引。批准字段如下：

| 字段 | 类型 | 可空/默认值 | 说明 |
|---|---|---|---|
| `id` | `BIGINT` | PK，identity | 内部链接记录 ID |
| `tenant_id` | `BIGINT` | NOT NULL | 租户隔离过滤 |
| `kb_id` | `BIGINT` | NOT NULL | KB 逻辑引用与链接解析范围 |
| `from_page_id` | `BIGINT` | NOT NULL | 发出 wikilink 的来源页面 |
| `to_page_id` | `BIGINT` | NULL | 已解析目标页面；目标尚不存在或被软删除时为空 |
| `target_slug` | `VARCHAR(255)` | NOT NULL，非空 | Markdown 中声明的不可变目标 slug；用于悬空链接和后续自动解析 |
| `created_at` | `TIMESTAMPTZ` | NOT NULL，默认 `now()` | 首次提取该链接的时间 |
| `updated_at` | `TIMESTAMPTZ` | NOT NULL，默认 `now()` | 链接解析状态更新时间 |

唯一性与索引：`UNIQUE(from_page_id, target_slug)`；建立 `(to_page_id, from_page_id)`、`(kb_id, target_slug)`、`(tenant_id, kb_id)` 索引。不建立数据库外键。

生命周期：保存页面时，在同一事务中更新正文、递增页面 `version` 并按当前 wikilink 集合物理删除/新增链接记录。同一目标出现多次只保存一条边；self-link 由解析器忽略。删除来源页面时物理删除其出边；删除目标页面时将入边的 `to_page_id` 清空并保留 `target_slug`；目标恢复或创建后重新补全 `to_page_id`。

字段边界：不保存 `public_id`、`source_page_version`、`link_type`、`weight`、显示文字、`in_links`、`out_links` 或 `deleted_at`。AI、Agent 和人工只修改页面正文，不直接写链接关系。

### `wiki_page_document_refs`

保存 Wiki 页面使用过的文档及具体不可变 Revision，是页面级来源清单。批准字段如下：

| 字段 | 类型 | 可空/默认值 | 说明 |
|---|---|---|---|
| `id` | `BIGINT` | PK，identity | 内部来源关系 ID |
| `tenant_id` | `BIGINT` | NOT NULL | 租户隔离过滤 |
| `kb_id` | `BIGINT` | NOT NULL | KB 隔离过滤 |
| `wiki_page_id` | `BIGINT` | NOT NULL | Wiki 页面逻辑引用 |
| `document_id` | `BIGINT` | NOT NULL | 稳定 Document 逻辑引用，用于文档导航和按文档反查页面 |
| `revision_id` | `BIGINT` | NOT NULL | 页面实际使用的不可变 Document Revision；文档产生新版时不自动漂移 |
| `created_at` | `TIMESTAMPTZ` | NOT NULL，默认 `now()` | 当前来源关系建立时间 |

约束与索引：`UNIQUE(wiki_page_id, revision_id)`；建立 `(tenant_id, kb_id)`、`(wiki_page_id, id)`、`(document_id, wiki_page_id)`、`(revision_id, wiki_page_id)` 索引。不建立数据库外键。应用必须验证 Revision 属于对应 Document，且页面、Document、Revision 位于同一租户和 KB。

生命周期：AI 生成或重新生成页面时，在同一事务中更新页面正文与版本，并整体替换当前文档来源集合。文档产生新 Revision 时旧页面仍锁定原 Revision，只有页面重新生成后才切换。页面软删除时保留来源以支持恢复；页面硬删除时由应用物理删除来源关系。

字段边界：不保存来源类型、权重、模型、Prompt、证据正文、`updated_at` 或 `deleted_at`。整篇摘要或宏观综合即使没有逐条证据，也可以保留文档级来源。

### `wiki_page_evidence_refs`

保存 Wiki 页面实际依据的精确原文证据。Wiki 从 Active Chunk Set 生成时同时保存快捷 chunk 关联、具体 Revision、准确原文引用和原文件位置；后三者是 chunk 被删除后仍然有效的长期证据。批准字段如下：

| 字段 | 类型 | 可空/默认值 | 说明 |
|---|---|---|---|
| `id` | `BIGINT` | PK，identity | 内部证据记录 ID |
| `tenant_id` | `BIGINT` | NOT NULL | 租户隔离过滤 |
| `kb_id` | `BIGINT` | NOT NULL | KB 隔离过滤 |
| `wiki_page_id` | `BIGINT` | NOT NULL | 使用这条证据的 Wiki 页面 |
| `document_id` | `BIGINT` | NOT NULL | 证据所属的稳定 Document |
| `revision_id` | `BIGINT` | NOT NULL | 证据所属的具体不可变 Revision |
| `evidence_quote` | `TEXT` | NOT NULL，非空 | 应用从共享 chunk 中核验复制的准确原文；不得信任 AI 自由改写后写入 |
| `evidence_sha256` | `CHAR(64)` | NOT NULL | 对 Revision、规范化位置和规范化引用计算的指纹，用于消除 chunk overlap 或 Wiki Map 批次重叠造成的重复证据 |
| `source_locator` | `JSONB` | NOT NULL | PDF 页码、标题路径、Excel sheet/行号、段落范围等原文位置；按媒体类型校验结构 |
| `content_chunk_id` | `BIGINT` | NULL | 生成证据时使用的共享 `content_chunks` 逻辑引用；MVP 正常生成时填充，该 chunk 删除后清空 |
| `created_at` | `TIMESTAMPTZ` | NOT NULL，默认 `now()` | 证据创建时间 |
| `updated_at` | `TIMESTAMPTZ` | NOT NULL，默认 `now()` | 清空 `content_chunk_id` 等关联状态的更新时间 |

约束与索引：`UNIQUE(wiki_page_id, evidence_sha256)`；建立 `(tenant_id, kb_id)`、`(wiki_page_id, id)`、`(document_id, revision_id)`、`(revision_id, wiki_page_id)`，以及 `content_chunk_id IS NOT NULL` 的 partial index。不建立数据库外键。`evidence_quote` 去除空白后不能为空；`evidence_sha256` 必须为 64 位小写十六进制。应用必须保证每条证据在 `wiki_page_document_refs` 中存在匹配的 `(wiki_page_id, document_id, revision_id)`；`content_chunk_id` 非空时，该 chunk 必须与证据属于同一租户、KB、Document 和 Revision，且 `evidence_quote` 必须能在 chunk 文本与 locator 范围内核验。

生命周期：生成页面时与页面正文、页面版本和文档来源集合在同一事务中整体替换，并填充当时的 `content_chunk_id`。关联 chunk 因 Revision 切换或重分块被物理删除前，应用先清空匹配证据的 `content_chunk_id`；保留 Revision、引用和位置，证据仍然有效。页面软删除时保留证据，硬删除时物理删除。

字段边界：不保存 `citation_no`、embedding、完整 Wiki Map 批次、完整 chunk 副本、模型、Prompt、`deleted_at` 或对外 `public_id`。来源列表需要编号时由查询或渲染层动态生成。

### `wiki_folders`

保存 Wiki 左侧目录树。`wiki_pages.folder_id` 是页面目录归属的事实来源；本表只保存单层父子关系，不缓存完整路径或深度。批准字段如下：

| 字段 | 类型 | 可空/默认值 | 说明 |
|---|---|---|---|
| `id` | `BIGINT` | PK，identity | 内部文件夹 ID |
| `public_id` | `UUID` | NOT NULL，自动生成 | API 使用的稳定公开 ID，全局唯一 |
| `tenant_id` | `BIGINT` | NOT NULL | 租户隔离过滤 |
| `kb_id` | `BIGINT` | NOT NULL | 文件夹所属 KB |
| `parent_id` | `BIGINT` | NULL | 父文件夹逻辑引用；NULL 表示 Wiki 根目录下的一级文件夹 |
| `name` | `VARCHAR(255)` | NOT NULL，非空 | 用户可见名称，允许修改 |
| `slug` | `VARCHAR(255)` | NOT NULL，非空，创建后不可修改 | 稳定且文件系统安全的 Markdown 导出路径段 |
| `sort_order` | `INTEGER` | NOT NULL，默认 `0` | 同一父目录内的人工排序权重 |
| `version` | `INTEGER` | NOT NULL，默认 `1`，且 `>= 1` | 移动、改名和排序时的乐观锁 |
| `created_by_user_id` | `BIGINT` | NULL | 创建者；系统创建时为空 |
| `updated_by_user_id` | `BIGINT` | NULL | 最近修改者；系统修改时为空 |
| `created_at` | `TIMESTAMPTZ` | NOT NULL，默认 `now()` | 创建时间 |
| `updated_at` | `TIMESTAMPTZ` | NOT NULL，默认 `now()` | 最近修改时间 |
| `deleted_at` | `TIMESTAMPTZ` | NULL | 软删除时间 |

唯一性与索引：`public_id` 全局唯一；未删除根级文件夹使用 partial unique index `UNIQUE(kb_id, slug) WHERE parent_id IS NULL AND deleted_at IS NULL`，未删除普通文件夹使用 partial unique index `UNIQUE(kb_id, parent_id, slug) WHERE parent_id IS NOT NULL AND deleted_at IS NULL`；建立 `(tenant_id, kb_id)`、`(kb_id, parent_id, sort_order, id)` 和 `parent_id` 索引。不建立数据库外键。

生命周期：展示改名只修改 `name`；`slug` 创建后不可修改。目录移动只修改 `parent_id` 并递增 `version`，应用必须验证新父目录属于同一租户和 KB，并禁止移动到自身或后代。非空文件夹不得直接删除，必须先移动或删除其子文件夹和页面；空文件夹采用软删除。

字段边界：不保存 `path`、`depth`、`children_ids`、页面数量或完整导出路径。移动目录会改变其后代的运行时导出路径，但不影响使用页面不可变 slug 的 Wiki 内部链接。

### `processing_runs`

保存一次完整处理任务的身份、目标、配置、状态和结果，是 `content_chunks.processing_run_id`、`content_chunks.embedding_run_id` 与 `wiki_pages.generation_run_id` 的运行主记录。批准字段如下：

| 字段 | 类型 | 可空/默认值 | 说明 |
|---|---|---|---|
| `id` | `BIGINT` | PK，identity | 内部运行 ID |
| `public_id` | `UUID` | NOT NULL，自动生成 | API、日志和排障使用的稳定公开 ID，全局唯一 |
| `tenant_id` | `BIGINT` | NOT NULL | 租户隔离过滤 |
| `kb_id` | `BIGINT` | NOT NULL | 运行所属 KB |
| `run_type` | `VARCHAR(50)` | NOT NULL | 应用注册的流程类型；MVP 包括 `source_sync`、`document_process`、`rag_index`、`wiki_generate` |
| `scope_type` | `VARCHAR(30)` | NOT NULL | 处理目标类型；MVP 包括 `source`、`revision`、`knowledge_base`、`wiki_page` |
| `scope_id` | `BIGINT` | NOT NULL | 由 `scope_type` 解释的处理目标逻辑 ID |
| `parent_run_id` | `BIGINT` | NULL | 上级编排运行；`rag_index` / `wiki_generate` 通常指向产生候选共享 chunk set 的 `document_process` Run |
| `retry_of_run_id` | `BIGINT` | NULL | 终态后发起业务重跑时指向上一 Run；RQ 自动重试不使用 |
| `attempt_no` | `INTEGER` | NOT NULL，默认 `1`，且 `>= 1` | 同一业务重跑链中的 Run 序号；RQ 自动重试不递增 |
| `trigger_type` | `VARCHAR(20)` | NOT NULL | `manual` / `on_ingest` / `schedule` / `retry` |
| `status` | `VARCHAR(20)` | NOT NULL，默认 `pending` | `pending` / `running` / `succeeded` / `failed` / `cancelled` |
| `idempotency_key` | `VARCHAR(255)` | NULL | 防止 API 重试或重复消息为同一请求创建多次运行 |
| `effective_config_version` | `INTEGER` | NULL，存在时 `>= 1` | 本次实际使用的 Source、KB 共享分块、RAG 或 Wiki 配置版本，由 `run_type` 解释 |
| `options_snapshot` | `JSONB` | NOT NULL，默认 `{}` | 共享分块策略、Wiki Map 批次预算、输出语言、Prompt profile 等实际生效的非敏感运行选项快照 |
| `requested_by_user_id` | `BIGINT` | NULL | 手动触发者；系统任务为空 |
| `error_code` | `VARCHAR(50)` | NULL | Run 进入失败终态时的稳定机器错误码；自动重试中的错误归 Span |
| `error_message` | `VARCHAR(1000)` | NULL | Run 进入失败终态时的简短错误摘要，不保存完整日志或堆栈 |
| `execution_token` | `UUID` | NULL | 当前执行权的 fencing token；领取 Run 时写入，提交终态/续租必须匹配（ADR-0018） |
| `execution_epoch` | `INTEGER` | NOT NULL，默认 `0`，且 `>= 0` | 单调递增的执行代号；每次原子领取 Run 时递增，用于拒绝过期 Worker 提交（ADR-0018） |
| `lease_expires_at` | `TIMESTAMPTZ` | NULL | 当前执行租约到期时间；未领取时为空（ADR-0018） |
| `worker_id` | `VARCHAR(255)` | NULL | 持有当前租约的 Worker 标识（ADR-0018） |
| `started_at` | `TIMESTAMPTZ` | NULL | 本 Run 第一次被 Worker 实际执行的时间，自动重试不覆盖 |
| `heartbeat_at` | `TIMESTAMPTZ` | NULL | 运行中最近心跳，用于发现卡死或崩溃任务 |
| `finished_at` | `TIMESTAMPTZ` | NULL | 成功、失败或取消的结束时间 |
| `created_at` | `TIMESTAMPTZ` | NOT NULL，默认 `now()` | 运行创建并进入等待队列的时间 |
| `updated_at` | `TIMESTAMPTZ` | NOT NULL，默认 `now()` | 状态、心跳或错误摘要的最近更新时间 |

约束与索引：`public_id` 全局唯一；`idempotency_key` 非空时 `UNIQUE(tenant_id, idempotency_key)`；`CHECK(status IN ('pending','running','succeeded','failed','cancelled'))`；租约形状 CHECK 保证 `(execution_token, lease_expires_at, worker_id)` 三者同时为空或同时非空。建立 `(tenant_id, kb_id, created_at DESC)`、`(run_type, status, created_at)`、`(scope_type, scope_id, created_at DESC)`、`parent_run_id`、`retry_of_run_id`、`(status, heartbeat_at)`、`(status, lease_expires_at)` 索引。不建立数据库外键。应用注册表校验 `run_type`、`scope_type` 及两者允许的组合，并验证目标、父运行和重试运行属于同一租户和 KB。续租、提交成功/失败均以 `execution_token` 与 `execution_epoch` 为条件，过期 Worker 的写入必须被拒绝（ADR-0018 fencing）。

生命周期：首次执行为 `pending -> running`。RQ 自动重试沿用同一 Run：当前执行失败但尚未耗尽队列重试预算时回到 `pending` 并清空 `heartbeat_at`，Worker 重新取得任务后再次进入 `running`；`started_at` 保留第一次实际执行时间。重试预算耗尽后才进入 `failed`。用户或系统对 `failed|cancelled` Run 发起业务重跑时创建新记录，填写 `retry_of_run_id` 并递增 `attempt_no`；旧终态记录不得覆盖为成功。`document_process` 成功后产生 `ready` 候选：未启用向量检索时直接激活并启动 `wiki_generate`；启用时先启动 `rag_index`，其成功触发激活并再启动 `wiki_generate`。`rag_index` 失败时父 Run 仍保持成功、旧 Active Revision 继续服务；`wiki_generate` 失败不回滚激活。运行记录没有软删除，按统一审计保留策略归档或清理。

字段边界：不保存完整日志、堆栈、阶段明细、队列消息正文、密钥、访问令牌或含义不稳定的“主要模型”。多个阶段使用的具体模型和细分指标由 `processing_spans` 保存。

### `processing_spans`

将一条 `processing_runs` 总任务拆成可观测的阶段树，保存阶段状态、耗时、模型 token、结构化指标和简短错误诊断。批准字段如下：

| 字段 | 类型 | 可空/默认值 | 说明 |
|---|---|---|---|
| `id` | `BIGINT` | PK，identity | 内部阶段 ID |
| `public_id` | `UUID` | NOT NULL，自动生成 | API 和日志追踪使用的稳定阶段 ID，全局唯一 |
| `tenant_id` | `BIGINT` | NOT NULL | 租户隔离过滤 |
| `kb_id` | `BIGINT` | NOT NULL | 阶段所属 KB |
| `run_id` | `BIGINT` | NOT NULL | 所属 `processing_runs` 逻辑引用 |
| `parent_span_id` | `BIGINT` | NULL | 上级阶段逻辑引用，用于表达嵌套阶段树 |
| `span_name` | `VARCHAR(50)` | NOT NULL | 应用注册的阶段名称，如 `parse`、`segment`、`extract_entities`、`embed` |
| `status` | `VARCHAR(20)` | NOT NULL，默认 `pending` | `pending` / `running` / `succeeded` / `failed` / `skipped` / `cancelled` |
| `model_key` | `VARCHAR(200)` | NULL | 该阶段实际使用的模型；非模型阶段为空 |
| `input_tokens` | `BIGINT` | NULL，存在时 `>= 0` | 模型阶段输入 token 数 |
| `output_tokens` | `BIGINT` | NULL，存在时 `>= 0` | 模型阶段输出 token 数 |
| `metrics` | `JSONB` | NOT NULL，默认 `{}` | 输入/输出项数、缓存命中、重试次数等阶段专属数值指标 |
| `error_code` | `VARCHAR(50)` | NULL | 稳定机器错误码 |
| `error_message` | `VARCHAR(1000)` | NULL | 简短错误摘要，不保存完整堆栈 |
| `started_at` | `TIMESTAMPTZ` | NULL | 阶段实际开始时间；尚未开始便跳过或取消时为空 |
| `finished_at` | `TIMESTAMPTZ` | NULL | 阶段结束时间 |
| `created_at` | `TIMESTAMPTZ` | NOT NULL，默认 `now()` | 记录创建时间 |
| `updated_at` | `TIMESTAMPTZ` | NOT NULL，默认 `now()` | 状态、指标或错误摘要更新时间 |

约束与索引：`public_id` 全局唯一；建立 `(tenant_id, kb_id)`、`(run_id, created_at, id)`、`parent_span_id`、`(status, started_at)`、`(model_key, started_at)` 索引。不建立数据库外键。应用必须验证 Run、父 Span 与当前 Span 属于同一租户、KB 和运行，并阻止 Span 层级循环。

生命周期：Span 创建时为 `pending`，实际开始后进入 `running`；正常完成进入 `succeeded`，阶段自身出错进入 `failed`，配置或输入决定不执行时进入 `skipped`，用户取消、Run 取消或上游失败造成中止时进入 `cancelled`。`pending` 可直接进入 `skipped|cancelled`，`running` 可进入 `succeeded|failed|cancelled`。`running|succeeded|failed` 必须有 `started_at`；所有终态必须有 `finished_at`；未开始的 `skipped|cancelled` 允许 `started_at IS NULL`。RQ 自动重试仍属于同一 Run，但应新增本次执行对应的 Span，不覆盖前一次执行的终态 Span。父阶段失败时，由编排器将尚未执行或仍在执行的依赖阶段标记为 `cancelled`。Span 不保存全局顺序号：固定阶段由应用注册表排序，同级动态 Span 按 `created_at, id` 排序，依赖关系只由编排代码定义。

字段边界：不保存原文、Prompt、完整模型响应、embedding、堆栈或完整日志。`metrics` 只接受注册的非敏感数值/布尔指标；阶段耗时由 `started_at` 与 `finished_at` 计算，不冗余保存 `duration_ms`。

| `expires_at` | `TIMESTAMPTZ` | NOT NULL | 按租户或部署保留策略计算的物理清理时间 |
| `updated_at` | `TIMESTAMPTZ` | NOT NULL，默认 `now()` | 用户反馈等可变字段更新时间 |

约束与索引：`public_id` 全局唯一；`feedback_value` 只能为 `-1`、`1` 或 NULL；建立 `(tenant_id, kb_id, created_at DESC)`、`(search_path, search_mode, created_at DESC)`、`(tenant_id, query_fingerprint)`、`user_id IS NOT NULL` 的 `(user_id, created_at DESC)` partial index、`feedback_value IS NOT NULL` 的 `(feedback_value, feedback_at)` partial index，以及 `expires_at` 索引。不建立数据库外键。

生命周期：搜索执行结果创建后保持不可修改，只允许补充或修改该请求的单用户反馈。到达 `expires_at` 后物理删除，不使用软删除。HMAC 密钥不进入数据库；命中对象删除后日志快照仍可用于历史统计，但公开 ID 可能不再可解析。

字段边界：不保存未经处理的原始查询、完整 Chunk/Wiki 正文、embedding、完整返回内容、模型输入或密钥。`result_snapshot` 的 JSON Schema 由应用版本化校验，默认不建立通用 GIN 索引，避免高写入成本。

## 表 9 Research Findings（审批依据）

1. Wiki 正文可能由 LLM、Agent 或人工编辑产生；`wiki_page_links` 不接受 AI 直接写入，而是由应用对最终保存的 Markdown 使用确定性解析器提取 `[[slug|显示文字]]`。
2. `target_slug` 保存 Markdown 中声明的目标。目标页面不存在时，`to_page_id` 为空，系统仍可据 `target_slug` 展示死链、生成待创建页面列表，并在目标页创建后补全解析。
3. wikilink 正则解析成本很低。已决定页面正文、页面 `version` 和链接集合在同一事务中同步保存，不存在旧异步链接任务覆盖新页面的问题，因此不保存 `source_page_version`。
4. 链接边与溯源边是两套不同关系：`wiki_page_links` 表达 Wiki 页面到 Wiki 页面的导航/关联；后续 `wiki_page_document_refs` 与 `wiki_page_evidence_refs` 表达 Wiki 页面到具体文档版本及原文证据的来源关系。
5. 已批准 MVP 的页面 slug 创建后不可修改，页面改名只修改 `title` 和 `aliases`；表 9 不需要承担 slug 重命名兼容。

## 最终跨表一致性复核

1. **身份与隔离通过**：对外稳定 UUID 统一命名为 `public_id`；需要租户过滤的高频业务表均显式保存 `tenant_id` 与 `kb_id`。
2. **文档血缘通过**：`Source -> Document -> Document Revision -> content_chunks` 可回到不可变原文件；Wiki 文档引用锁定具体 Revision，证据引用保存准确引文和原文位置。
3. **共享底座与双路径边界通过**：`content_chunks` 是 RAG/Wiki 共享的摄取产物；RAG embedding 与 Wiki Map/Reduce 作为独立子 Run 分别成败，Wiki 页面本身不写入 RAG 召回池。
4. **Wiki 三类关系通过**：页面导航链接、文件夹归属、原文溯源分别由独立表表达，不在 `wiki_pages` 中缓存数组或物化路径。

## WeKnora 专项研究结论（已完成）

- [x] 已阅读 WeKnora 原文件解析产物、Wiki 摄取、引用分批、合并去重和失败重试实现。

研究确认 WeKnora 的 RAG 和 Wiki 查询路径独立，但共享持久化 `chunks` 摄取底座；Wiki-only KB 也会生成 chunks，只是跳过 embedding。其 Map-Reduce 主要是“按文档 Map、按 Wiki slug Reduce”，并非“单篇长文分段 Map、文档内 Reduce”：候选实体和文档摘要使用重建后且最多 32768 字符的正文，只有引用分类遍历全部 chunks 并分批。引用批次失败可能被静默忽略；长期引用只保存 chunk ID，不保存准确 quote、locator 或不可变 Revision。

本项目采纳 WeKnora 的“共享持久化 chunks、下游能力独立”，以及按文档并行 Map、按 slug 并行 Reduce、同 KB 生成串行化、候选实体预筛、LLM 瞬态错误有限重试和短别名。不采纳重建整文后截断、部分证据静默成功、页面内 JSONB 引用数组或只保存可删除 chunk ID 的审计模型。

### 已批准的长文执行与恢复规则

1. 共享 chunk set 必须是确定性的，由 Revision、`chunking_config_version` 和实际运行选项生成；chunk 可少量重叠，但必须保留可核验的 `source_locator`。
2. Wiki 任务只读取目标 Document 的完整 Active Chunk Set；chunks 缺失、序号不连续或 Revision 不匹配时以稳定错误失败，不在 Wiki Worker 内暗中重新解析原文件。
3. 相邻 chunks 按 token 预算确定性地组合为 Map 批次；manifest 和 Map 结果只存在于当前 Worker 内存，不写入 Redis、`processing_runs` 或 `processing_spans`。
4. `processing_runs` 保存任务整体状态和心跳；`processing_spans.metrics` 保存总 chunk 数、总批次数、已完成批次数和当前 Worker 内重试次数，为进度查询的唯一事实来源。
5. 单个 LLM 请求的瞬态错误可在当前 Worker 内有限重试；Worker 退出、进程崩溃或队列重新执行时，从同一 Active Chunk Set 重新执行全部 Map，不跨运行复用中间结果。
6. 任一必需 Map 批次在有限重试后仍失败，则整个 Wiki 生成失败；未遍历全部 chunks 时不得部分更新 Wiki 页面。
7. 全部 Reduce 成功后，Wiki 页面、文档引用和证据引用在同一事务中提交；失败时不提交部分 Wiki 业务结果，也不重做原文解析和共享分块。
8. Redis 负责 RQ Job 投递、延迟重试和 Worker 消费，并保存可丢失的同 KB Wiki 租约锁与删除墓碑；不得保存 Wiki 业务进度、Map 结果或其他唯一业务副本。租约必须使用 owner token 和 Lua compare-and-renew/compare-and-delete；失锁 Worker 必须放弃提交。最终提交事务必须校验数据库中的删除、Active Revision、Run 状态和页面版本。
