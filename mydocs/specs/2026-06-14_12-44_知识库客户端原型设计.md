## 2. Research Findings (研究发现)

### 2.1 关键冲突点：用户意图与 PLAN.md 的差异

**PLAN.md 的设计**：Next.js Web 应用 → 用户通过**浏览器**访问 → Phase 4 用 Tauri 把 Next.js 打包成桌面应用。

**用户最新意图**："客户端不是浏览器哦"——明确要**直接做桌面应用**，不走浏览器路径。

**冲突解析**（待用户确认）：
- 选项 A：**沿用 PLAN.md**——先做 Next.js，再 Tauri 打包成桌面应用。最终用户双击 `.exe` 启动的是桌面应用，但开发期还是基于 Next.js
- 选项 B：**直接桌面优先**——跳过 Web 路径，直接用 Tauri/Electron + React/Vue 做桌面应用，省掉 Next.js 这层
- 选项 C：**纯原生桌面**——PySide6/Qt、Wails(Go)、.NET MAUI 等完全不走 Web 技术栈

**初步倾向**：选项 A——PLAN.md 已经定好，Tauri 包装 Next.js 是成熟方案，最终用户看到的确实是"桌面应用而非浏览器"。但需要确认用户是否接受"开发期看起来像浏览器（localhost:3000）"。

### 2.2 客户端需要的功能模块（基于 PLAN.md Phase 2 提炼）

| 模块 | 来源 PLAN.md | 核心价值 |
|---|---|---|
| AI 对话窗口 | Phase 0 + 2.4 | 主入口，知识库自动注入 |
| 文档管理 | Phase 2.2 | 浏览/导入/编辑 wiki 页面 |
| 知识图谱可视化 | Phase 2.3 | 实体关系力导向图 |
| 全局搜索 | Phase 2.5 | 关键词 + 向量混合检索 |
| 评估看板 | Phase 1 | P@k/MRR/nDCG 等指标展示 |
| 系统设置 | Phase 2 | 知识库切换、CLI 配置、API Key |
| 知识库管理 | "可插拔"段 | 挂载/卸载/快照/恢复 |

### 2.3 桌面客户端特有要素（PLAN.md 没覆盖）

PLAN.md 是按 Web 应用设计的，桌面客户端还要考虑：

| 要素 | 说明 |
|---|---|
| 系统托盘 | 最小化到托盘、快速打开 |
| 多窗口 | 文档对比、对话与文档并排 |
| 本地文件集成 | 拖拽文件导入、文件夹监控 |
| 全局快捷键 | 系统级唤起（如 Ctrl+Space） |
| 离线指示 | Claude API 不可用时的状态 |
| 启动屏 | 首次启动加载 LanceDB / 知识库 |
| 自动更新 | Tauri 自带 updater |
| 数据隔离 | 多知识库切换时的会话/上下文重置 |

### 2.4 桌面技术栈对比（待用户选）

| 技术栈 | 体积 | 上手 | 生态 | 备注 |
|---|---|---|---|---|
| **Tauri + Next.js/React** | ~10MB | 中 | 极好 | PLAN.md 原方案，Rust 壳 + WebView |
| **Tauri + Vue** | ~10MB | 中 | 好 | 比 React 轻量，模板语法直观 |
| **Electron + React** | ~150MB | 低 | 极好 | 体积大，VS Code/Discord 同款 |
| **Wails (Go) + React** | ~10MB | 中 | 好 | Go 后端，与 Python 工具链桥接需额外考虑 |
| **PySide6 (Qt)** | ~50MB+ | 高（Python） | 中 | 用户技术栈最熟，但企业感弱 |
| **.NET MAUI** | ~30MB | 高 | 中 | Windows 原生体验最好，但需学 C# |

**初步推荐**：Tauri + Next.js/React（沿用 PLAN.md）——理由：PLAN.md 已规划；最终体积最小；用户接受"开发期看起来像浏览器"。

## 5. Plan (详细设计与实现)

> **Innovate 跳过**：方案明确（HTML 静态原型 + 共享导航），无需多方案对比。

### 5.0 视觉设计系统（Editorial Knowledge Base）

> **设计哲学**：把这个产品做成"编辑级知识档案"，不是"AI 工具"。给老板和评委的感觉是"我们有沉淀"。
>
> **差异化记忆点**：
> 1. 中文标题用**宋体**（其他 AI 项目都是无衬线）
> 2. 米色背景（不是纯白）
> 3. **琥珀色**作强调（不是蓝紫渐变）
> 4. **编号化布局**（01、02、03）——编辑感
> 5. 衬线 + 等宽混排——杂志气质

#### 5.0.1 Typography（字体）

> **离线优先**：完全用系统自带字体，无 CDN 依赖，断网可用。Editorial 设计感通过 typography（字号/字重/字距/行距）和视觉系统其他元素（配色/装饰/编号）营造，不依赖 Webfont。

| 用途 | 字体栈 | 平台覆盖 |
|---|---|---|
| 中文标题 | `"Songti SC", "STSong", "SimSun", "NSimSun", serif` | ✓ Mac 宋体 / Windows SimSun |
| 英文标题 | `Georgia, "Times New Roman", Cambria, serif` | ✓ 全平台自带 |
| 正文 | `-apple-system, "PingFang SC", "Microsoft YaHei", "Helvetica Neue", sans-serif` | ✓ |
| 等宽 | `"SF Mono", "JetBrains Mono", Consolas, Monaco, "Courier New", monospace` | ✓ |

**字体加载策略**：纯 CSS `font-family` 栈，零网络请求。Mac 优先用 Songti SC（精致），Windows 退化为 SimSun（够用），Linux 退化为通用 serif。

**Editorial 感的营造方式**（不依赖 Webfont）：
- 字号对比强烈：标题 32-48px / 正文 14-15px / 元信息 12px
- 字重对比：标题 700 / 正文 400 / 元信息 500
- 字距控制：标题 `letter-spacing: -0.02em`，正文 `0`，标签 `0.08em uppercase`
- 行距：标题 1.2 / 正文 1.7（杂志感）/ 元信息 1.4
- 中英混排：中文用宋体，数字/英文 ID 用等宽，形成层次

#### 5.0.2 Color（配色）

```css
:root {
  /* 背景层 */
  --bg-page:      #FAF8F3;  /* 暖米色背景，不是纯白 */
  --bg-card:      #FFFFFF;  /* 卡片白 */
  --bg-soft:      #F5F2EB;  /* 二级背景（侧栏、抽屉）*/

  /* 文字层 */
  --ink:          #1C1917;  /* 主文字，近黑（带暖色温）*/
  --ink-muted:    #57534E;  /* 次要文字（warm gray）*/
  --ink-faint:    #A8A29E;  /* 极弱文字（placeholder、time）*/

  /* 强调色（唯一）*/
  --accent:       #B45309;  /* 琥珀色，CTA / 激活态 / 高亮 */
  --accent-soft:  #FEF3C7;  /* 琥珀色背景 */
  --accent-ink:   #78350F;  /* 琥珀色文字（深）*/

  /* 边框与阴影 */
  --border:       #E7E5E4;  /* 极淡边框 */
  --border-soft:  #F0EDE7;  /* 更淡 */
  --shadow-sm:    0 1px 2px rgba(28, 25, 23, 0.04);
  --shadow-md:    0 4px 12px rgba(28, 25, 23, 0.08);
}
```

**配色铁律**：单一强调色。全产品只在 CTA、激活态、关键高亮处使用 `--accent`，其他都是 ink + 米色 + 灰阶。

#### 5.0.3 Layout（布局）

- **网格**：严格 12 列网格，间距 24px
- **圆角**：6px（不要 `rounded-2xl` 的圆胖感）
- **阴影**：默认 `--shadow-sm`（极淡），悬停加深为 `--shadow-md`
- **Header**：固定顶部 56px，下边框 1px `--border`
- **Sidebar**：固定左侧 240px，背景 `--bg-soft`
- **Main Content**：剩余空间，最大宽度 1200px 居中
- **间距系统**：4 / 8 / 12 / 16 / 24 / 32 / 48 / 64（4 的倍数）

#### 5.0.4 Motion（动效）

克制为主，避免分散注意力：

- **加载动效**：staggered fade-in，每个模块延迟 60ms 出现，opacity 0→1 + translateY 4px→0
- **Hover**：背景色平滑过渡 150ms ease-out，无 transform
- **激活态**：左侧 2px 琥珀色边框 + 文字加深
- **流式输出**：光标闪烁 1.06s infinite + 已生成文字 fade-in 100ms
- **页面切换**：无路由动画（保持工具感）

#### 5.0.5 Decoration（装饰元素）

- **编号化**：所有列表/导航用 `01 02 03 04`（不是 emoji）
- **ASCII 装饰线**：`─ │ ┌ ┐ ╭ ╮` 用于分隔与强调（CSS ::before/::after）
- **纸张纹理**：极淡的 noise 纹理（SVG noise pattern，opacity 0.02）
- **引用标记**：内联引用用 `[01][02][03]` 风格，对应底部 sources 列表

### 5.8 技术选型

| 项 | 选择 | 理由 |
|---|---|---|
| HTML | HTML5 | 标准 |
| CSS | 原生 CSS + CSS Variables | 无构建依赖，浏览器直开 |
| JS | 原生 ES6 | 仅做交互（Tab 切换、节点点击），不引框架 |
| 图标 | **Lucide Icons SVG inline** | Editorial 风格需要专业图标，不用 emoji |
| 力导向图 | 内嵌 SVG 静态绘制 | 不引 D3，原型阶段够用；节点用宋体衬线 + 编号 |
| Mock 数据 | 内嵌 JSON | 让界面看起来真实，数据来自现有 wiki/ |
| 字体 | **系统字体栈（完全离线）** | Mac Songti SC / Windows SimSun + Georgia + 系统无衬线/等宽 |
