### Acceptance Criteria
1. `content_chunks` 存在 `USING bm25` 索引，`bm25_search` 走 `text ||| :q` + `paradedb.score(id)`，不再有 `ILIKE`。
2. 低于阈值的结果被过滤：vector 相似度 < 0.15 不返回；BM25 分数 < 0.3 不返回。
3. 过检索生效：top_k=10 时各路至少取 50 条候选，融合后截断 10。
4. RRF 权重正确：`score = 0.7/(60+rank_v) + 0.3/(60+rank_k)`（单路缺失该路贡献为 0）。
5. 每条 RetrievalResult 带 `match_type`；top-N 命中块带 `context`（相邻 chunk 列表）。
6. 新文档嵌入输入含文档标题前缀（旧数据不受影响）。
7. embedding Key 失效时 `search()` 降级为纯 BM25 检索，不报错 [2026-08-12 修订]。
8. 检索函数作为内部 service 可被外部模块（P1 SearchPlugin）直接调用 [2026-08-12 修订]。
9. 行为契约测试（service 层）全绿；人工用例验收通过（10~20 条记录到 §5）[2026-08-12 修订：测 service 不测 HTTP]。

## 2. Research Findings

### 事实与约束
1. **现状是 demo 级**：`bm25_search` 实为 `ILIKE '%q%'` + rank 恒 1.0 + `ORDER BY c.id`，无排序无分词（search.py L78-104）。
2. **基础设施已预留**：`001_initial.py` 注释"显式不做 pg_search BM25 索引（BM25 镜像就绪后另开任务）"；`content_chunks` 有 halfvec + `content_chunks_embedding_1024_hnsw` partial 表达式索引（`embedding::halfvec(1024)`）；`text_sha256` 指纹已存在。
3. **WeKnora 生产链路参数**（代码确认）：vector 阈值默认 0.15（score=1-distance）、keyword 阈值默认 0.3（ParadeDB score 归一化到 0-1）、过检索 `max(topk*5, 50)` cap 500、RRF k=60 权重 0.7/0.3、向量 SQL 子查询 expandedTopK(100-200)→阈值→TopK。
4. **ParadeDB**：pg_search 基于 Tantivy（Rust），BM25 + `chinese_lindera` 中文分词；`|||` 查询操作符 + `paradedb.score(id)` 打分；AGPL-3.0（自部署无影响）。官方镜像 `paradedb/paradedb`。
5. **zhparser 是死配置**：代码/migration 已废弃（test_initial_migration.py 断言 001 不含 zhparser），仅 `postgres/init-extensions.sql` 残留；ParadeDB 镜像不含 zhparser，换镜像前必须清理，否则 init 脚本失败。
6. **当前无存量 chunk**（用户确认），BM25 索引建在空表上，无需回填/重索引。
7. **嵌入写入点**：`rag_ingestion.py` L284 `embed_texts([chunk.text for chunk in candidates])`，标题前缀在此处构造。
8. **嵌入模型**：Jina embeddings v5（1024 维），query 侧 task=retrieval.query、passage 侧 retrieval.passage，已就绪。

### 风险与不确定项
- ~~ParadeDB 镜像 tag 与 PG16 兼容性需在执行时验证~~ → **已定 `paradedb/paradedb:v0.22.2-pg16`**（ParadeDB 官方支持 PG14+，`-pg16` tag 与现有 postgres_data 数据目录兼容；`-pg17` 会因大版本不兼容拒绝启动，升 PG17 需 pg_upgrade，另行任务）。
- 已有 postgres_data volume：换镜像不影响数据目录（扩展文件在 PG 安装目录），但 init-extensions.sql 只在首次初始化执行——已有 volume 需手动 `CREATE EXTENSION pg_search`（由 alembic 003 承担，天然幂等）。
- pg_search 对 text 列的 bm25 索引与现有 `ILIKE` 无冲突；`paradedb.score()` 在 JOIN 场景需子查询包裹（score 依赖匹配上下文）。
- 标题前缀改变嵌入语义：仅新文档生效（无存量，无副作用）。

### 4.2 Signatures [2026-08-12 修订：ChunkHit -> RetrievalResult，迁入 knowledge_bases/service/]
- `vector_search(db, kb_id, query_embedding, embedding_dim, top_k, threshold=0.15) -> list[RetrievalResult]`：子查询取 expandedTopK -> `distance <= 1-threshold` 过滤 -> TopK；`kb_id = ANY(:kb_ids)` 形式
- `bm25_search(db, kb_id, query, top_k, threshold=0.3) -> list[RetrievalResult]`：`WHERE text ||| :q` + 子查询 `paradedb.score(id) >= threshold` -> TopK
- `rrf_fuse(vector_results, bm25_results, k=60, vector_weight=0.7, keyword_weight=0.3) -> list[RetrievalResult]`
- `_over_retrieve_topk(limit) -> int`：`clamp(limit * RAG_OVER_RETRIEVE_FACTOR, MIN, CAP)`
- `_enrich_context(db, hits) -> None`：对 top-N 命中按 (document_id, revision_id) 批量取 `chunk_index ± 1`，填入 `hit.context`，match_type=nearby
- `search(db, kb_id, query, limit=10) -> list[RetrievalResult]`：编排（embed -> 双路过检索 -> 阈值过滤 -> 加权 RRF -> 截断 -> 增强）；**embedding 失效时降级为纯 BM25** [修订]
